# cuDNN Frontend 源码分析

依据 NVIDIA/cudnn-frontend 的 `develop` 分支提交 [`20f696cbd0b928dd6bacc907466dc16ab7fbb9a8`](https://github.com/NVIDIA/cudnn-frontend/tree/20f696cbd0b928dd6bacc907466dc16ab7fbb9a8)。以下为静态源码核对；未运行 GPU 正确性或性能测试。

## C++ Graph 前端与开放 kernel 的位置

仓库提供 header-only C++ Graph 前端与 Python 接口。Graph 的执行路径既可派发到仓库内的 OSS RMSNorm+SiLU 引擎，也可调用独立 cuDNN 后端的执行计划；看优化实现时，应继续追到具体 engine/kernel。见 [CMake INTERFACE target](https://github.com/NVIDIA/cudnn-frontend/blob/20f696cbd0b928dd6bacc907466dc16ab7fbb9a8/CMakeLists.txt#L26) 与 [Graph 执行派发](https://github.com/NVIDIA/cudnn-frontend/blob/20f696cbd0b928dd6bacc907466dc16ab7fbb9a8/include/cudnn_frontend/graph_interface.h#L1410)。

## CUDA C++ RMSNorm + SiLU

- **源码与 JIT 入口**：`include/cudnn_frontend/generated/rms_norm_silu/sm100/` 的两个头文件将 CUDA helpers 和 `ln_fwd_kernel` 内嵌为 C++ raw string。`experimental/sm100_rms_norm_silu_engine.h` 根据 shape/knobs 拼接编译常量，交给 NVRTC 编译为 CUBIN，再加载 kernel。见 [kernel 定义](https://github.com/NVIDIA/cudnn-frontend/blob/20f696cbd0b928dd6bacc907466dc16ab7fbb9a8/include/cudnn_frontend/generated/rms_norm_silu/sm100/ln_fwd_silu_kernel.h#L54) 与 [源码组装、编译及加载](https://github.com/NVIDIA/cudnn-frontend/blob/20f696cbd0b928dd6bacc907466dc16ab7fbb9a8/include/cudnn_frontend/experimental/sm100_rms_norm_silu_engine.h#L241)。
- **融合计算**：每行向量化加载输入，归约平方和并计算 reciprocal RMS，应用 gamma 后执行 SiLU；同一 kernel 继续完成 FP8 缩放/转换或 NVFP4 block-scale 量化。行遍历采用 grid-stride loop，可结合所选配置处理多行。见 [加载与 RMS 计算](https://github.com/NVIDIA/cudnn-frontend/blob/20f696cbd0b928dd6bacc907466dc16ab7fbb9a8/include/cudnn_frontend/generated/rms_norm_silu/sm100/ln_fwd_silu_kernel.h#L239) 与 [SiLU、量化及写回](https://github.com/NVIDIA/cudnn-frontend/blob/20f696cbd0b928dd6bacc907466dc16ab7fbb9a8/include/cudnn_frontend/generated/rms_norm_silu/sm100/ln_fwd_silu_kernel.h#L343)。
- **调优参数**：按 C、token 数及输出 dtype 选 WARPS_M、列拆分、persistent/非 persistent 配置、occupancy 与向量加载宽度；SM100+ 优先查 B200 测得的 LUT，未命中时回退到带整除检查的启发式。可参考 shape→配置→JIT 的组织方式，目标 GPU 上的收益仍需实测。见 [knob 定义](https://github.com/NVIDIA/cudnn-frontend/blob/20f696cbd0b928dd6bacc907466dc16ab7fbb9a8/include/cudnn_frontend/experimental/sm100_rms_norm_silu_knobs.h#L24) 与 [查表及回退](https://github.com/NVIDIA/cudnn-frontend/blob/20f696cbd0b928dd6bacc907466dc16ab7fbb9a8/include/cudnn_frontend/experimental/sm100_rms_norm_silu_knobs.h#L188)。
- **以实际实例化为准**：当前 engine 固定 BF16 输入/gamma，输出可选 BF16、FP8 E4M3、NVFP4；支持检查分别要求 SM80+、FP8 输出 SM89+、NVFP4 输出 SM100+。生成的常量关闭 `hasAmax` 和 `USE_CLUSTER`，因此源码模板里存在的 amax/cluster 分支不等于该引擎已启用。见 [类型与编译常量](https://github.com/NVIDIA/cudnn-frontend/blob/20f696cbd0b928dd6bacc907466dc16ab7fbb9a8/include/cudnn_frontend/experimental/sm100_rms_norm_silu_engine.h#L529) 与 [支持检查](https://github.com/NVIDIA/cudnn-frontend/blob/20f696cbd0b928dd6bacc907466dc16ab7fbb9a8/include/cudnn_frontend/experimental/sm100_rms_norm_silu_engine.h#L118)。

## CuTe-DSL block-sparse attention

- **输入语义与架构分路**：`block_sparse_attention_forward` 计算非 causal 稀疏 attention，调用者为每个 Q block 提供 KV block 列表；API 按 SM90、SM10x/11x、SM12x 与 64/128 block size 选择 CuTe-DSL 路径。不同路径的 head dimension、GQA 和 split-KV 能力不同；这个 wrapper 明确不包含旧 SM100 C++/AOT 扩展。见 [API 与约束](https://github.com/NVIDIA/cudnn-frontend/blob/20f696cbd0b928dd6bacc907466dc16ab7fbb9a8/python/cudnn/block_sparse_attention/api.py#L176)、[调用分路](https://github.com/NVIDIA/cudnn-frontend/blob/20f696cbd0b928dd6bacc907466dc16ab7fbb9a8/python/cudnn/block_sparse_attention/api.py#L270)。
- **稀疏访问与调度**：SM100 blk128 的 load loop 通过 `mBlockIndex` 把逻辑迭代映射到实际 KV block，交错 TMA 加载 K/V；persistent scheduler 可调用 CUTLASS 的 CLC 动态调度器。适合参考稀疏 gather 与不均匀工作项的组织方式。见 [KV load loop](https://github.com/NVIDIA/cudnn-frontend/blob/20f696cbd0b928dd6bacc907466dc16ab7fbb9a8/python/cudnn/block_sparse_attention/csrc/fwd/sm100_blk128/bsa_fwd_sm100.py#L930)、[CLC scheduler](https://github.com/NVIDIA/cudnn-frontend/blob/20f696cbd0b928dd6bacc907466dc16ab7fbb9a8/python/cudnn/block_sparse_attention/csrc/utils/block_sparse_tile_scheduler.py#L102)。
- **Blackwell attention 流水**：SM100 blk128 为 load、MMA、两组 softmax、correction 和 epilogue 分配不同 warp，S/P 与 O 使用两组 TMEM 槽；P 的前 3/4 写入 TMEM 后先通知 MMA，余下部分通过另一条 barrier 通知。可借鉴分段交付 P、重叠 softmax 与 PV 的实现。见 [warp/TMEM 配置](https://github.com/NVIDIA/cudnn-frontend/blob/20f696cbd0b928dd6bacc907466dc16ab7fbb9a8/python/cudnn/block_sparse_attention/csrc/fwd/sm100_blk128/bsa_fwd_sm100.py#L87)、[softmax 写回与通知](https://github.com/NVIDIA/cudnn-frontend/blob/20f696cbd0b928dd6bacc907466dc16ab7fbb9a8/python/cudnn/block_sparse_attention/csrc/fwd/sm100_blk128/bsa_fwd_sm100.py#L1445)。
- **边界与选型**：公开 SM100/SM110 blk128 前向只接受 `(QK,V)=(64,64)/(96,96)/(128,128)`；PackGQA 要求 GQA ratio 整除 128，且改变稀疏元数据的 head/block 布局。不能把内核内部更宽的 dimension 配置直接视为公开支持。见 [API 检查与元数据布局](https://github.com/NVIDIA/cudnn-frontend/blob/20f696cbd0b928dd6bacc907466dc16ab7fbb9a8/python/cudnn/block_sparse_attention/api.py#L217)。

## CuTe-DSL dense GEMM + SwiGLU

- **入口与选路**：`gemm/cutedsl/dense/swiglu/api.py` 的 `GemmSwigluSm100` 按是否提供量化参数选择普通 persistent GEMM 或 block-scaled kernel；公开调节项包括 MMA tile、cluster shape、scale vector size 和 AB12 stage 数。API 检查 compute capability 至少为 100；本文具体分析其 SM100 实现。见 [API 初始化与 kernel 选择](https://github.com/NVIDIA/cudnn-frontend/blob/20f696cbd0b928dd6bacc907466dc16ab7fbb9a8/python/cudnn/gemm/cutedsl/dense/swiglu/api.py#L31)、[架构检查](https://github.com/NVIDIA/cudnn-frontend/blob/20f696cbd0b928dd6bacc907466dc16ab7fbb9a8/python/cudnn/gemm/cutedsl/dense/swiglu/api.py#L372)。
- **低精度主循环**：专职 TMA warp 在 persistent loop 中搬运 A/B 及各自 scale，可进行 cluster multicast；MMA warp 把 scale 从 SMEM 复制至 TMEM，设置 `tcgen05.Field.SFA/SFB` 后执行 block-scaled GEMM。适合参考 FP4/FP8 数据与 scale 的流水配合。见 [TMA 与调度](https://github.com/NVIDIA/cudnn-frontend/blob/20f696cbd0b928dd6bacc907466dc16ab7fbb9a8/python/cudnn/gemm/cutedsl/dense/swiglu/dense_blockscaled_gemm_persistent_swiglu_interleaved_quant.py#L935)、[scale/TMEM 与 MMA](https://github.com/NVIDIA/cudnn-frontend/blob/20f696cbd0b928dd6bacc907466dc16ab7fbb9a8/python/cudnn/gemm/cutedsl/dense/swiglu/dense_blockscaled_gemm_persistent_swiglu_interleaved_quant.py#L1156)。
- **融合 epilogue 的实际内容**：up/gate accumulator 在寄存器中计算 `up * SiLU(gate)`，并按配置归约 amax 或生成输出 block scale、量化结果；同时仍将 AB12 中间值通过 TMA 写回，供 backward 使用。因此可参考激活与量化融合，但不能描述为完全消除中间张量写回。见 [AB12 写回与 SwiGLU](https://github.com/NVIDIA/cudnn-frontend/blob/20f696cbd0b928dd6bacc907466dc16ab7fbb9a8/python/cudnn/gemm/cutedsl/dense/swiglu/dense_blockscaled_gemm_persistent_swiglu_interleaved_quant.py#L1374)、[amax 与输出 scale](https://github.com/NVIDIA/cudnn-frontend/blob/20f696cbd0b928dd6bacc907466dc16ab7fbb9a8/python/cudnn/gemm/cutedsl/dense/swiglu/dense_blockscaled_gemm_persistent_swiglu_interleaved_quant.py#L1479)。

## CuTe-DSL MoE grouped GEMM + SwiGLU

- **按专家定位 tile**：`grouped/swiglu/grouped_gemm_swiglu_quant.py` 把 A/输出按专家连续拼接，以 `padded_offsets` 表示每个专家的范围；独立 scheduler warp 将 offsets 载入寄存器，在 persistent loop 中定位 tile 所属专家，并经共享内存 pipeline 向计算 warp 传递 tile 信息。API 编译时开启增量 expert 查找。见 [调度主循环](https://github.com/NVIDIA/cudnn-frontend/blob/20f696cbd0b928dd6bacc907466dc16ab7fbb9a8/python/cudnn/gemm/cutedsl/grouped/swiglu/grouped_gemm_swiglu_quant.py#L1555)、[编译配置](https://github.com/NVIDIA/cudnn-frontend/blob/20f696cbd0b928dd6bacc907466dc16ab7fbb9a8/python/cudnn/gemm/cutedsl/grouped/swiglu/api.py#L474)。
- **MoE epilogue 融合**：每个专家使用自己的 alpha，SwiGLU 结果可乘 token routing probability；同一 epilogue 按配置计算 amax，或生成行/列两个方向的量化输出与 scale。这是把 GEMM、激活、gating 与下游低精度布局结合的具体参考。见 [alpha、SwiGLU 与 probability](https://github.com/NVIDIA/cudnn-frontend/blob/20f696cbd0b928dd6bacc907466dc16ab7fbb9a8/python/cudnn/gemm/cutedsl/grouped/swiglu/grouped_gemm_swiglu_quant.py#L2365)、[双向量化](https://github.com/NVIDIA/cudnn-frontend/blob/20f696cbd0b928dd6bacc907466dc16ab7fbb9a8/python/cudnn/gemm/cutedsl/grouped/swiglu/grouped_gemm_swiglu_quant.py#L2471)。
- **variable-M 的约束**：这条实现的专家 token 数须按 `FIX_PAD_SIZE=256` padding，API 要求 `m_aligned=256`、tile/cluster 对齐与专家数不超过 1024；它不是直接接收任意无 padding ragged rows 的通用 grouped GEMM。见 [固定 padding 常量](https://github.com/NVIDIA/cudnn-frontend/blob/20f696cbd0b928dd6bacc907466dc16ab7fbb9a8/python/cudnn/gemm/cutedsl/grouped/swiglu/grouped_gemm_swiglu_quant.py#L184)、[API 对齐与专家数检查](https://github.com/NVIDIA/cudnn-frontend/blob/20f696cbd0b928dd6bacc907466dc16ab7fbb9a8/python/cudnn/gemm/cutedsl/grouped/swiglu/api.py#L407)。

## 调优时如何使用

基于上述执行路径的选型判断：优先将这里作为 Blackwell attention 流水、persistent dense/grouped GEMM、低精度 scale 布局与融合 epilogue 的实现参考。复用前沿调用入口核对架构、dtype、stride、padding 与中间输出约束；源码采用某种流水或融合方式，并不能证明它对目标 shape 一定更快。
