# MSA 源码分析

依据 MiniMax-AI/MSA 提交 [`80434d7f67877c6570ca19cac444b84bc9855dac`](https://github.com/MiniMax-AI/MSA/tree/80434d7f67877c6570ca19cac444b84bc9855dac)。以下为静态源码核对；未运行 GPU 正确性或性能测试。

## CuTe-DSL sparse prefill

- **K→Q 反向调度与 KV 复用**：每个工作项绑定一个 KV head、KV block 和引用该 block 的一段 Q 列表；CTA 加载 K/V 后，循环 gather 多组 Q，复用同一份 SMEM K/V 做 QK 与 PV。入口见 [`atten_fwd.py:689`](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/cute/src/sm100/fwd/atten_fwd.py#L689)，KV 加载见 [L1052](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/cute/src/sm100/fwd/atten_fwd.py#L1052)，循环使用同一 K/V fragment 见 [L1965](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/cute/src/sm100/fwd/atten_fwd.py#L1965) 与 [L2100](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/cute/src/sm100/fwd/atten_fwd.py#L2100)。
- **稀疏元数据与负载分配**：`prepare_k2q_csr.py` 实际调用 CUDA C++ builder；五阶段为 row-map、histogram、row-prefix、tile-prefix、scatter。row-prefix 顺便将高 fanout 的 CSR row 分成 Q chunks，scatter 为每条边记录 query 与 split slot，供前向写回和 combine 使用。见 [`build_k2q_csr.cu:623`](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/cute/src/sm100/build_k2q_csr/build_k2q_csr.cu#L623)、[L236](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/cute/src/sm100/build_k2q_csr/build_k2q_csr.cu#L236)、[L450](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/cute/src/sm100/build_k2q_csr/build_k2q_csr.cu#L450)。
- **分块结果合并**：prefill 输出每个 query 的 partial O/LSE；combine 先跨 split 做 log-sum-exp，再以归一化的 `exp(lse_i)` 权重累加 partial O。可借鉴的是“KV 复用 + split/combine”的完整组织方式。见 [`atten_fwd.py:2987`](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/cute/src/sm100/fwd/atten_fwd.py#L2987)、[`combine.py:779`](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/cute/src/sm100/fwd/combine.py#L779) 与 [L922](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/cute/src/sm100/fwd/combine.py#L922)。
- **Blackwell 实现细节**：TMA 搬运、专职 Q/KV load warp、MMA issue warp 与两个 softmax warpgroup 配合；S/P 和 O 使用 TMEM 双槽。MMA 交错发射 QK、PV；P 的前 3/4 写入 TMEM 后提前启动 PV，其余部分通过 mbarrier 等待。实际 tcgen05 PTX 见 [`blackwell_helpers.py:519`](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/cute/src/common/blackwell_helpers.py#L519)，流水线见 [`atten_fwd.py:130`](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/cute/src/sm100/fwd/atten_fwd.py#L130)、[L2079](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/cute/src/sm100/fwd/atten_fwd.py#L2079)、[L2314](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/cute/src/sm100/fwd/atten_fwd.py#L2314)。
- **稀疏 Q 的 gather**：`qhead_per_kv ∈ {1,2,4}` 使用 TMA gather4，将不连续 Q 行拼入 tile；`{8,16}` 走另一条 TMA Q-load 路径。见 [`atten_fwd.py:81`](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/cute/src/sm100/fwd/atten_fwd.py#L81)、[L1013](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/cute/src/sm100/fwd/atten_fwd.py#L1013)、[L1772](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/cute/src/sm100/fwd/atten_fwd.py#L1772)。
- **NVFP4 KV cache 与 FP4 MMA 要区分**：`atten_fwd_nvfp4_kv.py` 接受 BF16/FP8 E4M3 Q，把 packed NVFP4 K/V 经 TMA 载入后反量化为对应 Q dtype，再执行 BF16/FP8 QK、PV。文件头“BF16 Q”的注释没有覆盖实际 FP8 分支。见 [dtype 与 MMA 选择 L331](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/cute/src/sm100/fwd/atten_fwd_nvfp4_kv.py#L331)、[反量化 L1498](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/cute/src/sm100/fwd/atten_fwd_nvfp4_kv.py#L1498) 与 [TMA 后处理 L1802](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/cute/src/sm100/fwd/atten_fwd_nvfp4_kv.py#L1802)。
- **适用边界**：该 prefill kernel 固定 `head_dim=128`，GQA ratio 支持 `{1,2,4,8,16}`，paged KV 的 page size 须等于 block size；配套 CSR builder 只接受 `blk_kv=128`、`topK ∈ {4,8,16,32}`。见 [`atten_fwd.py:75`](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/cute/src/sm100/fwd/atten_fwd.py#L75)、[`prepare_k2q_csr.py:69`](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/cute/src/sm100/prepare_k2q_csr.py#L69) 与 [L107](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/cute/src/sm100/prepare_k2q_csr.py#L107)。

## FP4 block-score indexer

- **计算内容**：使用原生 tcgen05 block-scaled FP4 MMA，支持 MXFP4（32 元素共享 E8M0 scale）与 NVFP4（16 元素共享 E4M3 scale）。每个 Q/head 对每个 128-token KV page 计算 QK 最大值，输出 FP32 block scores；top-k 由调用者完成。见 [`fp4_indexer.py:49`](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/cute/src/sm100/fp4_indexer.py#L49)、[MMA 选择 L311](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/cute/src/sm100/fp4_indexer.py#L311)、[MMA 调用 L862](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/cute/src/sm100/fp4_indexer.py#L862)、[max/store L1001](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/cute/src/sm100/fp4_indexer.py#L1001)；公开导出在 [`sparse.py:17`](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/sparse.py#L17)。
- **可借鉴优化**：scale 预重排为 MMA layout；scale 经 SMEM→TMEM 后与 FP4 数据一起参与 GEMM；K/scales 的 TMA load、MMA、两个 epilogue warpgroup 通过三槽管线协作。见 [`fp4_indexer_interface.py:885`](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/cute/fp4_indexer_interface.py#L885)、[`fp4_indexer.py:223`](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/cute/src/sm100/fp4_indexer.py#L223)、[L776](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/cute/src/sm100/fp4_indexer.py#L776)、[L885](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/cute/src/sm100/fp4_indexer.py#L885)。
- **短 Q 特化与架构边界**：`max_seqlen_q<=8` 且 GQA ratio=16 时，把 Q token/head 打包为 128 行 MMA tile；TMEM load+max-reduce 指令只在 capability `>=10.3` 启用，SM100 走 TMEM load 后 max 归约。见 [`fp4_indexer_interface.py:899`](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/cute/fp4_indexer_interface.py#L899)、[`fp4_indexer.py:1189`](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/cute/src/sm100/fp4_indexer.py#L1189)、[`fp4_indexer_interface.py:47`](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/cute/fp4_indexer_interface.py#L47)。

## C++ FMHA、Top-K 与 decode

- **两条 attention 调用链**：根 API 的 sparse prefill 通过 adapter 构造 K→Q CSR 后调用 CuTe-DSL；短 Q 的 sparse 路径将请求展开为 per-token 工作项，进入 C++ FMHA。其 loader 先从 `kv_block_indexes` 取逻辑页，再经 `kv_indices` 找物理页，并用 TMA 载入 K/V，因而确实实现了稀疏 decode。见 [`api.py:533`](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/api.py#L533)、[`sparse_fmha_adapter.py:344`](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/sparse_fmha_adapter.py#L344)、[`sm100_fmha_load_tma_warpspecialized.hpp:528`](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/csrc/include/sm100_fmha_load_tma_warpspecialized.hpp#L528)。
- **C++ score-only 与 Top-16**：`OnlyScore` 特化跳过 V 加载，将 QK 的每块最大值直接写出；selector 将 scores 转置成行连续布局，经直方图阈值筛选、候选排序，再用单 warp bitonic 按页索引排序，同时将越界页改为尾部 `-1`。公开 `sparse_topk_select` 固定 `topk=16`、要求 `max_k_tiles<12288`，不能与 prefill 接口的 `{4,8,16,32}` 混为一谈。见 [score-only 写回](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/csrc/include/sm100_fmha_fwd_mainloop_tma_warpspecialized.hpp#L950)、[V-load 特化](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/csrc/include/sm100_fmha_load_tma_warpspecialized.hpp#L72)、[selector 主体](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/csrc/include/sparse_topk_select.cuh#L659)、[公开参数检查](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/api.py#L1226)。
- **CuTe decode 的实际边界**：`sparse_decode_atten_func` 和 `SparseDecodePagedAttentionWrapper` 的稀疏分支最终在 `q2k_indices` 非空时抛出 `NotImplementedError`；已实现的是全量 paged FP8 decode。公开路径限制 FP8 E4M3 Q/K/V、D=128、GQA ratio=16、causal，kernel 要求 page size=128。见 [`interface.py:1578`](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/cute/interface.py#L1578)、[wrapper 路由](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/cute/interface.py#L1373)、[输入检查](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/cute/interface.py#L476)、[kernel 约束](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/cute/src/sm100/fwd_decode/atten_fwd.py#L80)。
- **全量 decode 仍有调优参考价值**：PackGQA 将 token/head 合并成 Q tile，通过 TMA 整块载入；tcgen05 QK/PV、TMEM、专职 load/MMA/softmax/correction warps 配合 CLC persistent scheduler。长 KV 可 split 成多个工作项，再以 FP32 partial O/LSE combine；wrapper 的 plan/run 复用调度及工作区。见 [`fwd_decode/atten_fwd.py:298`](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/cute/src/sm100/fwd_decode/atten_fwd.py#L298)、[`tile_scheduler.py:116`](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/cute/src/sm100/fwd_decode/tile_scheduler.py#L116)、[`fwd_decode/__init__.py:77`](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/cute/src/sm100/fwd_decode/__init__.py#L77)、[`interface.py:1282`](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/cute/interface.py#L1282)。

## Benchmark 范围

`benchmarks/bench_sparse_attention_ops.py` 的 BF16/FP8 sparse 项先为所有 token 固定选择前 Top-K 页，再计时 `fmha_sm100` 调用；其中 prefill 会经过 adapter 的 CSR 构造与 combine，但该计时不包含 block-score indexer 或 Top-K 选块。评估完整 MSA 链路时，应另测这些阶段，并使用有代表性的选块分布。见 [固定页索引与计时边界](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/benchmarks/bench_sparse_attention_ops.py#L380) 与 [prefill adapter](https://github.com/MiniMax-AI/MSA/blob/80434d7f67877c6570ca19cac444b84bc9855dac/python/fmha_sm100/sparse_fmha_adapter.py#L361)。

## 选型判断

基于上述执行路径的推断：此项目最有价值的参考是 Blackwell 上将稀疏访问重组为 KV 复用的 tile 计算，以及低精度 indexer/cache 与 attention 管线的配合。收益需要连同 CSR 构造、partial 写回、combine、scale reorder/短 Q packing 的开销一起测量；源码结构不能证明任意 shape 或稀疏分布下都有加速。
